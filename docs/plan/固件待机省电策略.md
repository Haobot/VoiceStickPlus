# 固件待机省电策略设计方案

> 状态：设计稿，待评审（2026-06-23 据官方文档修正唤醒链路）
> 范围：仅固件 `firmware/`（桌面端联动见第 10 节）
> 目标板：M5Stack StickS3（ESP32-S3），PMIC=M5PM1（I2C 0x6e），IMU=BMI270（I2C 0x68/0x69，SCL=G48/SDA=G47）
>
> **关键硬件事实（已由 M5Stack 官方文档确认，见第 8 节）**：
> 1. BMI270 的 **INT1 引脚接 M5PM1 的 PYG4**，**不接 ESP32-S3 任何 GPIO**。因此 ESP32 无法用 ext1/gpio_wakeup 被 IMU 直接唤醒；"拿起唤醒"走 **PMIC 级**路径——保持 IMU(L1) 供电 → M5PM1 休眠 → 翻转触发 IMU 中断经 PYG4 唤醒 M5PM1 → ESP32 重新上电（冷启动）。
> 2. M5PM1 **支持软件关机**（Arduino 库 `pm1.shutdown()`），对应写 M5PM1 关机寄存器。S3 走真关机路径可行，固件 C 层复用 `pmic_write_reg/update_reg` 写对应位即可。

## 1. 背景与问题

当前固件已有一套两级省电链路：

```
30s 无操作 → Resting 画面（背光降到 8/255）→ 5min 无操作 → deep sleep（背光 0 + panel off）
```

但存在以下问题，导致待机时间短、需每天一充：

1. **Resting 态屏幕仍亮**：背光仅降到 8（约满量程 3%），持续放电，这是待机功耗主因之一。
2. **deep sleep 被 BLE 连接阻断**：`deep_sleep_allowed_now()`（`main.c:154-158`）要求 `!voice_ble_is_connected()`。也就是说只要桌面端连着，设备永远不进 deep sleep，CPU/无线长期满载待机。
3. **无"拿起唤醒"**：唤醒源只有前键 GPIO11（ext1）。用户必须按键才能恢复，体验差。
4. **无真正关机**：只有 deep sleep，仍由 PMIC 供电；长时间不佩戴也只睡不关。
5. **断连后不关机**：断连仅重新广播 + 5min deep sleep（且仅电池态），USB 供电时永不睡。

## 2. 设计目标

- 在 BLE 连接始终保持的前提下，分级降低功耗。
- 支持"按键"和"拿起（BMI270 检测）"两种唤醒方式，拿起即亮屏，最快速恢复工作。
- 长时间无使用且无佩戴时自主关机（真断电或等价），最大节约电能。
- BLE 断连超时自动关机。
- USB 供电时不关机（避免充电中关机），但仍可熄屏。

## 3. 目标状态机

将现有两级扩展为**四级电源状态** + **BLE 断连旁路**：

```
                        任意态按键 / 拿起
                          ┌─────────────┐
                          ▼             │
   ┌─────────┐  T_rest   ┌─────────┐  T_off   ┌──────────┬─ T_pwr(连接态) ──> ┌──────────┐
   │  S0     │ ────────> │  S1     │ ───────> │  S2      │ ─────────────────> │  S3      │
   │ Active  │           │ Resting │          │ ScreenOff│                     │ PowerOff │
   │ 背光32  │ <───────  │ 背光8   │ <──────  │ 背光0    │ <─── 按键/拿起 ──── │ (断电)   │
   └─────────┘  按键/拿起 └─────────┘  按键/拿起 └──────────┘                    └──────────┘
       │                                                                                  ▲
       │                       BLE 断连：启动 T_disc 倒计时，到期 ─────────────────────────┘
       └── BLE 重连取消 T_disc 倒计时
```

状态定义：

| 状态 | 含义 | 背光 | Panel | CPU/无线 | BLE | 录音 |
|------|------|------|-------|----------|-----|------|
| **S0 Active** | 正常交互 | 32 | on | 活跃（idle 时 tickless 自动 light sleep） | 连接 | 可录音 |
| **S1 Resting** | 待机画面 | 8 | on | 同 S0（light sleep 深度介入） | 连接 | 否 |
| **S2 ScreenOff** | 熄屏保连 | 0 | on（保留，见 4.3） | light sleep 深度（BT modem sleep + 主 XTAL 保活） | **连接保持** | 否 |
| **S3 PowerOff** | 关机 | 0 | off | 断电 / deep sleep | 断开 | 否 |

### 转移条件

- `S0 → S1`：`T_rest`（默认 30s）无按键活动。已有逻辑。
- `S1 → S2`：`T_off`（默认 60s）无按键且无拿起。**新增**。
- `S2 → S3`：`T_pwr`（默认 10min）无按键且无拿起。**新增**（连接态关机）。
- `S1/S2 → S0`：按键 或 拿起（BMI270）。**新增拿起**。
- `任意 → S0`：按键。
- **BLE 断连旁路**：断连即启动 `T_disc`（默认 10min）倒计时，期间设备停在 S1/S2 省电态并重新广播；到期 → S3。重连则取消倒计时回正常状态机。**新增**。

## 4. 各状态省电逻辑

### 4.1 S0 / S1（已有，沿用）

- S0：背光 32，正常交互。
- S1：背光 8，渲染 Resting 猫画面（`ui_status_set_idle_dimmed(true)`）。
- 两态 CPU 均靠已启用的 tickless idle（`CONFIG_FREERTOS_USE_TICKLESS_IDLE=y`）自动 light sleep；BLE 靠 BT modem sleep mode 1 + 主 XTAL 保活（`CONFIG_BT_CTRL_MAIN_XTAL_PU_DURING_LIGHT_SLEEP=y`），连接不掉。

### 4.2 S2 ScreenOff（新增，核心省电点）

进入动作：
1. `ui_status_set_brightness(0)` —— 背光归零（独立于显示逻辑，`ui_status.c:374-381`）。
2. 保留 LVGL/panel 状态，不关 panel（见 4.3）。
3. 置 `s_screen_off=true`，停止 `s_display_dim_timer` 与 `s_display_off_timer`，保留 `s_poweroff_timer` 继续走。
4. 让 tickless light sleep 自然加深：由于无 UI 刷新、无录音，CPU 大量时间进 light sleep，BT controller 在连接间隔间睡眠。

省电来源：背光 0（待机功耗大头消除）+ CPU light sleep 加深。BLE 连接参数建议在 S2 切到 slow 模式（连接间隔拉大，如 200ms，`voice_ble.c:896` 已有 slow 参数逻辑可复用），进一步降功耗。

> 关键：S2 不是 deep sleep，因此 BLE 连接保活，唤醒无需重连，满足"最快速恢复"。

### 4.3 Panel on/off 权衡

- **方案 A（推荐）**：S2 只关背光，保留 panel on。唤醒只需 `ui_status_set_brightness(32)`，毫秒级恢复，无需 panel re-init。
- **方案 B（功耗优先）**：S2 额外 `esp_lcd_panel_disp_on_off(panel, false)`。省电更多，但唤醒需 re-init panel + 重刷整帧，恢复慢约 200~500ms，且需在 LVGL 锁内小心处理。
- 默认采用 A；若实测 S2 待机电流仍偏高（目标 <1mA 量级），再切 B。

### 4.4 S3 PowerOff（新增/改造关机）

**路径 A：真·关机（M5PM1 软件关机，已确认可行）**
- M5PM1 支持软件关机（Arduino `pm1.shutdown()`，见第 8 节）。新增 `stick_s3_board_power_off()`，用现有 `pmic_write_reg/update_reg` 写关机寄存器位（具体位待 datasheet 确认，见 8.2）。
- 关机前执行官方推荐序列：保持 L1(IMU) 供电 + 锁定 + 配置 PYG4 为 IMU 唤醒源（见 6.2.1）。
- 关机后仅 L0 + L1 供电，整机电流降至 IMU 低功耗检测级（目标 μA~低 mA 量级）。
- 唤醒：按键（M5PM1 按键开机硬件路径）或 拿起（IMU 中断经 PYG4 唤醒 M5PM1）→ ESP32 上电冷启动。

**路径 B（退化备份）：长期 deep sleep**
- 若 M5PM1 关机寄存器位一时无法确认，复用现有 `enter_deep_sleep()`（`main.c:297-388`），解除"BLE 连接阻断"限制。
- 功耗接近关机级但高于路径 A（ESP32 deep sleep 仍耗电），唤醒=按键 ext1 冷启动，**无 IMU 唤醒**（INT1 不接 ESP32）。
- 作为路径 A 未就绪时的过渡方案。

**采用顺序**：先实现路径 B 保证可用（仅需改 `deep_sleep_allowed_now` 准入条件 + 计时器），并行查 datasheet 落实路径 A 的关机位与 PYG4 配置，再升级到 A 以获得 IMU 拿起唤醒。

两条路径对外部行为一致：唤醒后冷启动，桌面端重新配对/连接。

## 5. 唤醒源设计

> ⚠️ 重要修正：BMI270 INT1 接 M5PM1 PYG4，**不接 ESP32**（见第 8 节）。因此唤醒分两类：ESP32 在线时由 ESP32 处理；ESP32 关机后由 M5PM1 处理。

| 唤醒方式 | S1→S0 | S2→S0 | S3→开机 |
|----------|:-----:|:-----:|:------:|
| 前键/侧键 | ✅（iot_button，已有） | ✅（iot_button `enable_power_save`，已有） | ✅（M5PM1 按键开机，已有硬件路径） |
| 拿起（BMI270） | ✅（ESP32 在线：BMI270 INT1→PYG4 不可直达 ESP32，需 ESP32 轮询 BMI270 中断状态寄存器，或读 M5PM1 PYG4 状态） | ⚠️（ESP32 light sleep 下无法被 IMU 直接唤醒；靠低频 esp_timer 周期唤醒短暂轮询，或退化为仅按键唤醒） | ✅（M5PM1 关机级：保持 L1(IMU) 供电，翻转触发 IMU 中断经 PYG4 唤醒 M5PM1 → ESP32 上电冷启动） |

**关键结论**：
- S3 关机态的"拿起唤醒"由 **M5PM1 + IMU 硬件链路**完成，ESP32 不参与，冷启动恢复——这是官方推荐的低功耗唤醒路径，完美匹配本需求。
- S1/S2 在线态的"拿起亮屏"因 INT1 不接 ESP32，只能 **ESP32 主动轮询**（低频 esp_timer 读 BMI270 中断状态），无法靠中断被动唤醒。代价是轮询功耗，但 S1/S2 本就允许 light sleep 间隙唤醒。
- 若 S2 轮询功耗不可接受，可让 S2 直接跳过、尽快进入 S3（靠 M5PM1 级 IMU 唤醒），即"S1 → 短暂后 → S3"两级简化。

按键唤醒链路已完备，本方案主要新增"拿起唤醒"——核心落在 S3 的 M5PM1 关机 + IMU 保持供电链路。

## 6. BMI270 拿起检测方案

### 6.1 驱动组件（新增）

新建 `firmware/components/bmi270/`，结构仿 `stick_s3_board`：

```
components/bmi270/
├── CMakeLists.txt          # REQUIRES: driver esp_driver_i2c stick_s3_board
├── include/bmi270.h
└── bmi270.c
```

- 复用 `stick_s3_board_i2c_bus()` 句柄，`i2c_master_bus_add_device` 以 0x68（SDO=GND）/0x69（SDO=VDD）添加设备节点（参照 `stick_s3_board.c:113-118`）。
- 使用新 I2C master API（`driver/i2c_master.h`，与现有一致）。

**实现路线（已决策：路线 2，分阶段差异化）**：
- **阶段 1 在线态（S0/S1/S2）**：纯轮询，**不加载 8KB config file blob**。`softreset` → `PWR_CTRL=0x7D=0x04`(开 ACC) → 配 `ACC_CONF=0x40` ODR。低频 esp_timer（500ms）读 `ACC_X_LSB`(0x0C) 6 字节，软件算合加速度差分，超阈值判定拿起 → 投 `APP_EVENT_PICKUP`。理由：INT1 接 PYG4 不到 ESP32，feature 中断的 INT 输出在线态无被动唤醒价值，轮询即可，省 8KB flash。
- **阶段 3 关机态（S3）**：那时才加载 8KB config file，配 any-motion feature + INT1 push-pull 输出，让 IMU 在关机后低功耗检测、翻转经 PYG4 唤醒 M5PM1。

API 草案：
  - `esp_err_t bmi270_init(void)` —— 探测 CHIP_ID(0x00，应为 0x24)，失败则置 `s_present=false`，禁用拿起唤醒（优雅降级）。开 ACC，初始化轮询基线。
  - `bool bmi270_present(void)` —— 供状态机查询。
  - `bool bmi270_pickup_detected(void)` —— 轮询用：读 ACC 6 字节，软件差分判定是否拿起（内部维护上次合加速度基线）。触发后内部重置基线避免重复。
  - `esp_err_t bmi270_enable_pickup_wake(void)` —— **阶段 3 用**：加载 config file + 配 any-motion + INT1 输出，为关机后 PYG4 唤醒做准备。
- 在 `main/CMakeLists.txt` 的 `REQUIRES` 追加 `bmi270`；`app_main` 中 `stick_s3_board_init()` 之后、`audio_pipeline_init()` 附近调用 `bmi270_init()`。

**BMI270 寄存器事实（已由 Bosch 官方 BMI270-Sensor-API 源码确认）**：
- CHIP_ID 寄存器 0x00，期望值 0x24。I2C 地址：SDO=GND→0x68，SDO=VDD→0x69（7-bit）。
- softreset：写 0x7E=0xB6，等 2ms。
- `PWR_CTRL`=0x7D，bit2=ACC_EN(0x04)。`PWR_CONF`=0x7C。`ACC_CONF`=0x40。
- ACC 数据：`ACC_X_LSB`=0x0C，6 字节（X/Y/Z 各 2 字节 little-endian，LSB 4 bit + MSB 8 bit，14-bit 左对齐）。
- 阶段 3 feature 路径：config file 8192 字节（`bmi270_config_file[]`），分块 burst 写 0x5E（每块先写 word 地址到 0x5B/0x5C）；`INIT_CTRL`=0x59；`INTERNAL_STATUS`=0x21，INIT_OK=0x01；any-motion 在 feature page 1 offset 0x0C（threshold 0x68=50mg、duration 0x01=20ms、xyz_sel=0xE0、enable bit7=0x80）；`INT1_MAP_FEAT`=0x56，any-motion=bit6(0x40)；`INT1_IO_CTRL`=0x53（push-pull+active low+out_en=0x08）；`INT_LATCH`=0x55；状态位 `INT_STATUS_0`=0x1C bit6(0x40)。

### 6.2 INT 引脚连接（已确认，修正原设计）

**硬件事实**：BMI270 INT1 接 **M5PM1 PYG4**，**不接 ESP32-S3 任何 GPIO**（见第 8 节）。原方案假设的"情形 1：INT 已引出到 ESP32 GPIO"作废。

由此带来的实现约束：

- **ESP32 在线时（S0/S1/S2）**：无法用 GPIO ISR 被动接收 IMU 中断。两种获取方式：
  - (a) **ESP32 主动轮询** BMI270 的中断状态寄存器（如 `INT_STATUS_1` 0x1C），低频 esp_timer（默认 500ms）周期读。S1/S2 态执行；S2 下定时器周期性把 CPU 从 light sleep 唤醒短暂读数再睡。
  - (b) 读 **M5PM1 PYG4 的 GPIO 输入状态寄存器**（若 M5PM1 把 PYG4 状态映射到可读寄存器），同样需轮询。优先 (a)。
- **ESP32 关机时（S3）**：ESP32 不参与，唤醒完全由 M5PM1 + IMU 硬件链路完成（见 4.4 / 8.1）。这是 S3 拿起唤醒的唯一可行路径，也是官方推荐路径。
- **不需要** `STICK_S3_PIN_IMU_INT` 宏，也**不需要** ext1 / gpio_wakeup 配置 IMU INT。

### 6.2.1 S3 关机 + IMU 唤醒实现（核心新增）

进入 S3 时执行官方推荐序列（C 层映射）：

1. `bmi270_enable_pickup_detect()` —— 配置 BMI270 any-motion 特性与 INT1 输出（INT1 接 PYG4）。
2. 保持 L1(IMU) 供电并锁定：写 M5PM1 `LDO3V3_EN_PP` 使能 + `HOLD_CFG` 的 LDO_HOLD 位（对应 `M5PM1_HOLD_CFG_LDO_HOLD BIT(5)`，待核实）。
3. 配置 M5PM1 PYG4 为 IMU 唤醒源（写对应寄存器位，datasheet 待确认）。
4. `stick_s3_board_power_off()` —— 写 M5PM1 关机寄存器位（对应 `pm1.shutdown()`）。
5. M5PM1 关机，仅 L0 + L1 供电；IMU 低功耗检测中；翻转 → IMU 中断经 PYG4 唤醒 M5PM1 → ESP32 上电冷启动 → `app_main` 正常启动 → BLE 重新广播/连接。

退出（唤醒后）：冷启动走正常 `app_main` 流程，无状态恢复需求。

### 6.3 拿起检测算法

优先用 BMI270 内置 **any-motion**（加速度差分超阈值）或 **sig-motion** 特性，阈值经验值（待实测标定）：
- any-motion 阈值：~0.2~0.3g，持续时间 ~1~2 个采样。
- 唤醒后立即 `bmi270_clear_motion()`，避免重复触发。
- 防误触：连续 2 次间隔 <300ms 的 motion 才判定为"拿起"；或要求加速度幅值变化超过静态基线一定量。

> BMI270 的 any-motion / sig-motion 配置需加载初始化固件（feature engine），实现细节参考 Bosch 官方 `bmi270` driver 示例。本方案不手写传感器融合，仅用内置特性。

## 7. 计时器与事件改动（`main.c`）

### 7.1 新增/改造计时器

| 计时器 | 类型 | 周期 | 状态 | 作用 |
|--------|------|------|------|------|
| `s_display_dim_timer` | one-shot | `T_rest`=30s | 已有 | S0→S1 |
| `s_display_off_timer` | one-shot | `T_off`=60s | **新增** | S1→S2 |
| `s_poweroff_timer` | one-shot | `T_pwr`=10min | **改造**（原 `s_deep_sleep_timer`） | S2→S3（连接态） |
| `s_disc_poweroff_timer` | one-shot | `T_disc`=10min | **新增** | BLE 断连→S3 |

### 7.2 计时器管理逻辑

改造 `note_activity()`（`main.c:275-288`）为状态感知：

- S0 活动时：重启 `dim` + `off` + `poweroff` 三个计时器；进入 S1 时停止 `dim`、保留 `off`+`poweroff`；进入 S2 时停止 `dim`+`off`、保留 `poweroff`。
- 拿起事件与按键一样调 `note_activity()`（重置全部计时器并回 S0）。
- `T_pwr` 到期条件需放宽：现有 `deep_sleep_allowed_now()` 要求 `!voice_ble_is_connected()`，需新增"连接态关机"判定函数 `poweroff_allowed_now()`，允许 BLE 连接下关机（但要先优雅断开或接受断连）。

### 7.3 新增事件

- `APP_EVENT_DISPLAY_OFF` —— S2 进入。
- `APP_EVENT_PICKUP` —— BMI270 拿起（ISR 或轮询投递）。
- `APP_EVENT_ENTER_POWER_OFF` —— S3 进入（可复用现有 `APP_EVENT_ENTER_DEEP_SLEEP` 并加分支）。

### 7.4 BLE 断连旁路（`main.c:822-836`）

在 `APP_EVENT_BLE_DISCONNECTED` 现有处理（停录音、回配对、`restart_deep_sleep_timer`）基础上：
- 启动 `s_disc_poweroff_timer`（`T_disc`）。
- 到期 → S3 关机。
- `APP_EVENT_BLE_CONNECTED` 时 `esp_timer_stop(s_disc_poweroff_timer)` 取消。
- USB 供电时（`is_external_powered()`）禁用关机（含 `T_pwr` 与 `T_disc`），仅允许到 S2 熄屏。

- M5Stack 官方库源码 `m5stack/M5Unified`（`src/utility/Power_Class.cpp`）与 `m5stack/M5PM1`（`src/M5PM1.h` / `.cpp`）

### 8.1 板级电源架构（已确认）

- **BMI270 INT1 → M5PM1 GPIO4（即"PYG4"）**，不接 ESP32-S3 任何 GPIO。官方原文：「IMU 的 INT1 中断引脚连接至 M5PM1 的 PYG4，可通过配置相关的寄存器实现保持 IMU 供电，M5PM1 进入休眠状态，通过翻转设备，触发 IMU 中断唤醒 M5PM1。」
- **多级电源 L0–L3B（非串联，可独立控制）**：
  - L0：M5PM1 自身（电池直供），始终保持，支持按键开关机。
  - L1：**IMU** 供电，开关 `LDO3V3_EN_PP`（PWR_CFG bit2）。
  - L2/L3A：ESP32-S3 + Grove/Hat/红外/按键。ESP32 deep sleep=L2，工作=L3A。
  - L3B：LCD 背光/MIC/SPK，开关 GPIO2（即现有 `M5PM1_GPIO2_L3B_POWER_EN`）。

### 8.2 M5PM1 关键寄存器（已落实，来自 M5PM1 库源码）

| 寄存器 | 地址 | 相关位 | 说明 |
|--------|------|--------|------|
| `REG_PWR_CFG` | **0x06** | bit2=LDO_EN / bit3=BOOST_EN / bit4=LED_EN / bit0=CHG_EN / bit1=DCDC_EN | L1(IMU) 供电开关 = bit2；复位/下载时自动清零 |
| `REG_HOLD_CFG` | **0x07** | bit5=LDO 电源保持 / bit4=GPIO4 / bit3=GPIO3 / bit2=GPIO2 / bit1=GPIO1 / bit0=GPIO0 | 锁定各路供电保持 |
| `REG_SYS_CMD` | **0x0C** | [7:4]=密钥 0xA，[1:0]=CMD：01=关机 / 10=复位 / 11=下载 | **软件关机寄存器**：写 `0xA1` = 关机 |
| `REG_WAKE_SRC` | **0x05** | bit5=外部 GPIO 唤醒（写 0 清除标志） | 唤醒源标志 |
| `REG_GPIO_MODE` | 0x10 | [4:0] GPIO 方向，1=输出 | — |
| GPIO4 功能 | **0x17** | [1:0]：00=GPIO / 01=IRQ / **10=WAKE** / 11=PWM1 | **把 GPIO4(PYG4) 配为 WAKE 模式 = IMU 唤醒源** |
| GPIO4 上下拉 | 0x15 | [1:0]：00=无 / 01=上拉 / 10=下拉 | 配 INT1 触发电平的上下拉 |

固件现有 `stick_s3_board.c` 已有 `M5PM1_REG_PWR_CFG 0x06`、`M5PM1_PWR_CFG_LDO_EN BIT(2)`、`M5PM1_HOLD_CFG_LDO_HOLD BIT(5)`、`M5PM1_GPIO2_L3B_POWER_EN BIT(2)`——与官方源码**完全一致**，证实现有寄存器定义正确。需新增：`REG_SYS_CMD=0x0C`、`REG_WAKE_SRC=0x05`、`REG_GPIO4_FUNC=0x17`、`REG_GPIO4_PUPD=0x15` 及对应位。

### 8.3 关键 API → 固件 C 实现映射（已落实）

官方 Arduino API 的底层实现已从源码确认，固件 C 层直接照搬寄存器操作即可：

| Arduino API | 源码实现 | 固件 C 等价 |
|-------------|---------|-------------|
| `pm1.setLdoEnable(true)` | `setPowerConfig(LDO_EN, LDO_EN)` → PWR_CFG(0x06) bit2 置位 | `pmic_update_reg(0x06, BIT(2), BIT(2))` |
| `pm1.ldoSetPowerHold(true)` | HOLD_CFG(0x07) bit5 置位 | `pmic_update_reg(0x07, BIT(5), BIT(5))` |
| `pm1.setLedEnLevel(true)` | PWR_CFG(0x06) bit4(LED_EN) 置位 | `pmic_update_reg(0x06, BIT(4), BIT(4))` |
| `pm1.shutdown()` | `sysCmd(SYS_CMD_OFF)` → 写 SYS_CMD(0x0C) = `0xA0 \| 0x01` = **0xA1**，写前 delay 120ms | `pmic_write_reg(0x0C, 0xA1)`（前置 120ms 延时） |
| 配置 PYG4 为 IMU 唤醒源 | GPIO4 功能寄存器 0x17 [1:0]=10(WAKE) + `gpioSetWakeEnable(GPIO4)` | `pmic_update_reg(0x17, 0x03, 0x02)` + WAKE_SRC 使能 |

**关机 + IMU 唤醒完整序列（固件 C 层）**：
```c
// 1. 保持 L1(IMU) 供电并锁定（关机后 LDO 不掉电，IMU 继续低功耗检测）
pmic_update_reg(0x06, BIT(2), BIT(2));   // PWR_CFG.LDO_EN = 1
pmic_update_reg(0x07, BIT(5), BIT(5));   // HOLD_CFG.LDO_HOLD = 1
pmic_update_reg(0x06, BIT(4), BIT(4));   // PWR_CFG.LED_EN level = 1（官方序列含此步）
// 2. 把 GPIO4(PYG4) 配为 WAKE 模式，作为 IMU INT1 唤醒源
pmic_update_reg(0x17, 0x03, 0x02);       // GPIO4 func = WAKE
// （上下拉 0x15 按 BMI270 INT1 有效电平配，待实测）
// 3. 软件关机
vTaskDelay(pdMS_TO_TICKS(120));          // 官方 sysCmd 写前 delay 120ms
pmic_write_reg(0x0C, 0xA1);              // SYS_CMD = 0xA0(KEY) | 0x01(OFF)
// 关机后：仅 L0+L1 供电，IMU 低功耗检测；翻转 → INT1 → PYG4 → 唤醒 M5PM1 → ESP32 上电冷启动
```

> 注：M5Unified 的 `_powerOff(false)`（即 `powerOff()`）对 M5PM1 走的是写 0x0C=0xA1（同上），但仅在 `!withTimer` 时执行；`shutdown()`（withTimer=true）走 ESP32 deep sleep 而非 PM1 关机。本方案要的是**真关机**，直接用上面的 0x0C=0xA1 序列，不依赖 M5Unified 的 deep sleep 分支。

### 8.4 仍需实测确认的细节

1. **BMI270 I2C 地址**：0x68 还是 0x69（SDO 电平），开机自检两种都探测。
2. **BMI270 any-motion 配置**：阈值/持续时间需实测标定（参考 Bosch 官方 `bmi270` driver 的 any-motion feature 示例，需加载 BMI270 初始化固件到 feature engine）。
3. **GPIO4(PYG4) 上下拉与 INT1 触发电平**：BMI270 INT1 默认 active-high 还是 active-low，需配 0x15 寄存器上下拉匹配，待实测。
4. **StickS3 批次差异**：早期 StickS3 用 MPU6886，较新用 BMI270。自检若读不到 BMI270 CHIP_ID(0x24)，探测 MPU6886(0x68, WHO_AM_I=0x70) 作兼容路径，或禁用拿起唤醒。
5. **关机后 BLE 断连的桌面端体验**：可选关机前 state_tx 上报 `power_state:"power_off"` 提示桌面端。

## 9. 配置项与默认值

固件侧暂用编译期宏（`main.c` 顶部），后续如需运行时可调再纳入 BLE control 配置：

```c
#define DISPLAY_DIM_TIMEOUT_MS       (30 * 1000)   // T_rest，已有
#define DISPLAY_OFF_TIMEOUT_MS       (60 * 1000)   // T_off，新增
#define POWEROFF_TIMEOUT_MS          (10 * 60 * 1000) // T_pwr，新增（连接态）
#define DISC_POWEROFF_TIMEOUT_MS     (10 * 60 * 1000) // T_disc，新增（断连）
#define PICKUP_POLL_INTERVAL_MS      (500)         // 轮询退化周期，新增
#define BMI270_ANYMOTION_THRESHOLD   /* 实测标定 */
```

默认值依据：T_rest 沿用现有 30s；T_off 60s 给用户短暂离开后回来"看一眼就亮"的窗口；T_pwr/T_disc 10min 覆盖"放下设备去忙别的"典型场景。最终值待实测功耗与体验调校。

## 10. 桌面端 / 协议联动

- **S2 熄屏**：BLE 不断，桌面端无感知，无需协议改动。可选：固件在电量上报 JSON 中追加 `power_state` 字段（`"active"|"resting"|"screen_off"`），供桌面端 UI 显示设备省电态（非必需）。
- **S3 关机**：BLE 断开，桌面端按现有断连处理（`APP_EVENT_BLE_DISCONNECTED` 路径），无需新协议。
- **拿起唤醒后**：设备回 S0，BLE 仍在（S2 唤醒）或重连（S3 唤醒），桌面端无需特殊处理。
- 文档：若新增 `power_state` 上报字段，同步更新 `docs/protocol.md` 的 state_tx 帧说明。

## 11. 风险

| 风险 | 影响 | 缓解 |
|------|------|------|
| ~~BMI270 INT 未引出~~ | ~~S3 无法 IMU 唤醒~~ | 已确认 INT1 接 M5PM1 PYG4，S3 可走 PMIC 级 IMU 唤醒（见 6.2.1） |
| ~~M5PM1 无软件关机位~~ | ~~S3 只能 deep sleep~~ | 已确认 `pm1.shutdown()` 存在，路径 A 可行 |
| M5PM1 关机位 / PYG4 寄存器位未落实 | 路径 A 暂不可用 | 先上路径 B（deep sleep）过渡，并行查 datasheet / M5Unified 源码确认位 |
| S1/S2 在线态 IMU 只能轮询 | 轮询功耗 + 唤醒延迟 | 低频（500ms~1s）轮询；S2 不可接受则缩短 S2 提前进 S3 |
| 拿起误触发 | 桌面振动误唤醒 | BMI270 any-motion 阈值标定 + 双确认逻辑；可配置关闭 |
| S2 下 BLE slow 间隔影响录音响应 | 录音开始延迟 | 进入录音时立即切回 fast 连接参数（已有切换逻辑） |
| USB 供电误关机 | 充电中关机 | `is_external_powered()` 守卫关机路径（T_pwr / T_disc） |
| 固件无单元测试框架 | 状态机回归靠手测 | 编译期 `assert` + 详尽手测清单；状态转移用日志可观测 |
| 关机后 BLE 断连 | 桌面端可能频繁重连告警 | 桌面端按现有断连处理；可选 state_tx 提前上报 `power_state:"power_off"` 提示 |

## 12. 实施步骤（建议分阶段提交）

**阶段 0：硬件事实落实**
- ✅ INT1 接 M5PM1 PYG4（已确认）。
- ✅ M5PM1 支持软件关机（已确认）。
- ✅ 查 M5Unified / M5PM1 源码落实：关机寄存器位（SYS_CMD 0x0C = 0xA1）、PYG4 唤醒源配置位（GPIO4 func 0x17 [1:0]=10 WAKE）、LDO_HOLD 位（HOLD_CFG 0x07 bit5）——见第 8 节。
- ⬜ BMI270 I2C 地址探测（0x68/0x69）、批次兼容（MPU6886）——编码时自检实现。

**阶段 1：BMI270 驱动 + 运行态轮询唤醒**
- 新建 `components/bmi270/`，实现 init/探测/any-motion 配置/中断状态轮询接口。
- `app_main` 接入初始化（`stick_s3_board_init` 之后）。
- 低频 esp_timer 轮询 BMI270 中断状态，S1 态检测到拿起投 `APP_EVENT_PICKUP` → `note_activity` 亮屏回 S0。
- 手测：S1 态拿起设备能亮屏。

**阶段 2：S2 ScreenOff + 三级计时**
- 新增 `s_display_off_timer`，改造 `note_activity` 状态感知。
- S2 进入只关背光（方案 A），关 L3B 层供电（`stick_s3_board_prepare_deep_sleep` 已有关 L3B 逻辑，可复用为"仅关 L3B 不进 deep sleep"变体）。
- S2 下轮询继续（或评估停轮询、提前进 S3）。
- 手测：30s→Resting、60s→熄屏（背光 0 + L3B 关）、BLE 保连；按键回 S0。

**阶段 3：S3 关机实现（先 B 后 A）**
- 路径 B：改造 `deep_sleep_allowed_now` 放宽（允许连接态关机），`T_pwr` 到期进 deep sleep。USB 守卫。
- 路径 A（datasheet 就绪后）：`stick_s3_board_power_off()` + 6.2.1 官方序列（保持 L1 + PYG4 唤醒源 + shutdown）。手测关机后翻转设备能冷启动唤醒。

**阶段 4：BLE 断连自动关机**
- 新增 `s_disc_poweroff_timer`，接入 `APP_EVENT_BLE_DISCONNECTED/CONNECTED`。
- USB 守卫。

**阶段 5：联调与功耗实测**
- 各状态实测待机电流，标定 BMI270 阈值与超时。
- 同步 `docs/protocol.md`（若加 `power_state`）。

## 13. 测试计划

固件无自动化测试框架，以手测清单 + 日志观测为主：

- [ ] 开机 BMI270 自检：读到 CHIP_ID=0x24，日志打印 `bmi270 ok`；读不到则 `bmi270 absent, pickup wake disabled`，设备仍正常工作。
- [ ] S0→S1：30s 无操作进入 Resting，背光降到 8。
- [ ] S1→S2：再 60s 背光归 0（用光照/电流观测），BLE 连接保持（桌面端不断连）。
- [ ] S2→S0（按键）：按前键，毫秒级亮屏回 Active。
- [ ] S2→S0（拿起）：拿起设备，亮屏回 Active（INT 或轮询路径分别验证）。
- [ ] S2→S3：10min 无操作关机；电流仪确认断电级功耗。
- [ ] S3 唤醒：按键冷启动恢复。
- [ ] BLE 断连关机：主动断开桌面端，10min 后关机；重连则取消。
- [ ] USB 供电：插电时 T_pwr/T_disc 不触发关机，但 S2 熄屏仍生效。
- [ ] 录音响应：S2 下发起录音，连接参数切 fast，无显著延迟。
- [ ] 功耗实测：S2 待机电流目标显著低于现状（背光 0），S3 接近断电级。
