# 本地小模型目标词对齐——多模型闭环评测报告（2026-10-28 凌晨）

> 任务来源：2026-10-27 深夜准确率排查（`voice-targeted-accuracy-baseline-2026-10-27.md`）
> 定位出三层损失，其中 **B 层（ASR 指令轮目标词漂移，≈27%）** 适合本地小模型兜底。
> 本文给出候选约束式对齐层的多模型横评与推荐。方法可复现：
> `scripts/local_align_bench/`（闭环 = 数据集 → 真实 Core 候选/请求构造 → 本地 ollama →
> 同口径解析 → 自动打分）。

## 一、结论（TL;DR）

- **推荐 `qwen2.5:1.5b-instruct`（Q4，986MB）**：主集对齐 16/17（94%）、负例 NONE 6/7，
  **留出集（全新词汇）8/10、NONE 4/4、零危险误选**，稳态延迟 ~80ms（冷启首呼 ~1.1s）。
  无过拟合迹象，温度 0 下三连跑结果稳定。
- 意外发现（与 M0 跨轮纠错结论**相反**）：qwen3 家族（1.7B/4B）与 qwen2.5:3b 在本任务的
  「few-shot + 结构化约束输出」形态下全面保守崩塌（答 NONE 过多）；反而 1.5b 段位最稳。
  **不同任务形态的模型结论不可互相搬用，必须实测。**
- gemma3:1b 是备选（NONE 全对但正例 13/17 且误选 6）；qwen2.5:0.5b 留出集意外有 7/10
  但主集仅 5/17，不推荐；qwen3:4b 延迟 520ms+ 且对齐弱，不推荐。

## 二、任务定义与安全模型

- 触发条件（生产）：自然简写解析命中、但目标词在最近注入 `remainingText` 中 0 精确匹配
  （即门控回退前）。对齐层尝试把听漂的目标词映射回真实子串。
- 三段式（对齐 Windows 跨轮纠错「模型出指令、守卫代码层执行」的 house pattern）：
  1. **拼音预筛**（纯逻辑，PinyinGuard 同表分级评分）：remainingText 连续窗口，
     长度=目标±1；等长窗口阈值 0.4（低分召回档，如「分析/升旗」仅 0.45）、非等长 0.9
     （挡垃圾单词）；**重叠簇内只留与目标等长者**（否则「升旗/看升旗/旗」让全模型选错）。
  2. **本地模型挑选**：ollama `/api/chat`，`think:false`，`temperature:0`，JSON-schema
     结构化输出 `{reason, answer}`，answer **枚举硬约束=候选+NONE**（杜绝格式逃逸）；
     few-shot 5 例（3 正 2 负，assistant 带真实短理由）。
  3. **确定性校验执行**：模型答案必须精确命中候选枚举（代码再验一遍），随后走**原封不动**
     的 verified 选区/读回/终验链——模型无法制造文本里不存在的编辑对象；NONE/失败/超时
     一律回退普通文本（现行行为）。

## 三、评测设置

- 主集 29 例：真实失败样本 7（含 2026-10-27 晚 session 43/44/45、38/39、旧构建 12）+
  同音/近音/掉字合成 15 + 负例 7；其中 **gate 桶 2 例**（目标是 remaining 子串，生产中
  exact 门控直接通过、根本不进对齐）与 **poisoned 桶 3 例**（remaining 是上一轮失败指令
  的粘贴文本；C 层修复后同样不进对齐）单独分桶，不计入正/负例指标。
- 留出集 14 例（10 正 4 负）：全部新句新词（杭州/张伟/牛奶/评审/成本/深圳/五楼/数据库/
  手机/进度），与主集及 few-shot 零重叠，验证泛化。
- 环境：Apple M4 Pro / 24GB，ollama 0.40.3（Q4 默认量化），温度 0，非流式单轮。

## 五、迭代记录（为什么是现在这个形态）

三轮关键修复，每轮都有全模型对照数据支撑：

1. **重叠窗口变体是全模型杀手**：首版候选含「升旗/看升旗/旗」「北京/去北京/北京上」，
   所有模型（含 4b）都在词边界上犯错（选「看升旗」「我今天」等）。修复=重叠簇内只留
   与目标等长的候选后，1.5b 正例 10/18→16/17。
2. **负例垃圾单词应在预筛层消灭**：非等长窗口阈值提到 0.9 后，4/7 负例零候选直接 NONE。
3. **纯枚举直出会教坏小模型**：无 reason 槽时 1.5b 负例只 1/10 NONE；结构化
   `{reason, answer}` + few-shot 带真实短理由后升到 6/7。注意 few-shot 的 reason 用
   占位符「…」会把 qwen3 全体带成 NONE 崩塌——理由必须是真实示范。

## 六、遗留与风险

- poisoned 桶（r2/r3/r5）在**无 C 层修复**时可被对齐层「合理地」选错对象（如 r3 在
  「把身体改成烤鸭。」里选「身体」——语义上完全讲得通）。结论重申：**C 层
  （isCommandFallback 标记 + 门控跳过）应先行或同批落地**，否则对齐层会放大错编辑面。
- 延迟代价：对齐轮 +80ms（1.5b 稳态）；最坏 timeout（默认 3s）期间 mainInputState 处于
  finalizing，新按键被忽略（现有 busy 语义，无竞态；代价是最坏 3s 锁窗）。
- 模型输出温度 0 仍有批间抖动的理论可能（ollama mmap 采样），reps=3 未观察到；
  生产依赖「答案必须命中候选枚举」兜底，任何抖动最坏退化为 NONE 回退。
- 未跑：llama3.2:3b / qwen3:8b（拉取未完成，当晚链路慢）；qwen3 系已知崩塌，qwen3:8b
  大概率同形态，后续可用 harness 一键补测。
- Windows 侧未实现（见方案 §17.7 待办）。
