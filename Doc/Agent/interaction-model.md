# 核心交互模型（状态表与按键语义）

本文承载核心交互模型的完整细节，2026-08 由根目录 `AGENTS.md`/`CLAUDE.md` 的「核心交互模型」章节迁入；根指南只保留状态机归属红线与指向本文的指针。

固件上报原始按键事实，桌面端解释为交互行为并回写 `ui_state`：

| 状态 | 主键（正面） | 侧键 |
|---|---|---|
| 未配对/未连接 | 不录音，屏幕显示 `VS-XXXX` | 无有效动作 |
| 连接空闲 | 按住开始录音（双击直接注入 Enter，不录音） | 双击恢复上一次输入确认；单击无操作（体感鼠标入口已移除） |
| 录音中 | 释放结束录音 | 单击不取消当前录音 |
| 识别中 | 忽略新录音 | 单击取消正在进行的识别 |
| 确认倒计时中 | 暂停自动粘贴，进入手动确认 | 单击取消待粘贴文本 |
| 手动确认中 | 确认粘贴 | 单击取消待粘贴文本 |

补充说明：

- 双击检测在固件端完成（小米遥控器语音键则在桌面端适配层完成，阈值见 `Doc/Plan/primary-button-double-click.md` / `[device.<id>.xiaomi]` 的 `double_click_ms`），桌面端统一处理 `button_double_click`：主键双击取消当前活跃录音/字幕后注入 Enter；侧键双击执行「恢复上一次输入确认」（体感鼠标态下忽略）。小米遥控器无侧键，其余 HID 键由 OS 原生消费。
- 小米遥控器**长按连发**（macOS，2026-10-15 起，直连 + 网关双路径）：除语音键外的可映射键按住时，首发后按 `[buttons]`/`[device.<id>.buttons]` 的 `repeat_delay_ms`（默认 300ms）/`repeat_interval_ms`（默认 80ms）节拍重复注入直至抬起——对齐系统键盘自动重复；直连路径由 `XiaomiButtonInterceptManager`（inject 动作）消费，网关路径由协调器 `gateway_key` 双沿消费（key/native 动作皆连发，disabled 不连发）。连发集合 = `RemoteButton.supportsRepeat`（仅排除 `voice_double_click`，语音键走 ATVV 层不经键路）。按键映射对话框有「长按连发」延迟/间隔滑块（两种模式共用，节拍为表级全局值）。
- 侧键单击的取消语义仅在有活跃录音/识别/待粘贴时生效；体感鼠标态下单击退出体感；真正空闲时单击无操作（体感入口已移除，`ToggleAirMouse` 不再由侧键触发）。
- 另有敲击检测（`tap_to_arrow` 配置，IMU 敲击映射为方向键），体感态下忽略。

支持 `hold_to_talk`（默认）和 `click_to_talk` 两种交互模式。文本输出支持三种目标：`focused_app`（默认粘贴到当前焦点，默认自动按 Return）、`subtitle`（仅显示字幕）和 `wechat_input_method`（把 Opus 解码为 PCM 渲染到系统虚拟麦克风，供微信输入法等应用作为音频输入源，不经 ASR 文本注入）。识别结果可通过 OpenAI-compatible LLM 做翻译与精修，也可按设备单独覆盖输出设置。

- **语音编辑指令**（v2.4.10 起，macOS + Windows，`[voice_edit]` 配置，默认开启）：一次正常的按住/点按说话会话，ASR final 文本若整句命中编辑指令（"删除/删掉最后两个字"、"删除最后一句"、"删除刚才的/撤销/撤回"、"删除"单独说默认删 1 字），桌面端在精修/翻译/粘贴之前本地解析并执行，不把命令文本上屏；删除作用于最近一次语音注入到 `focused_app` 的文本尾部（按字/句/整段），执行手段为向焦点应用注入 N 次退格（`auto_enter` 的换行按实际字段额外计入）。安全边界：仅最近一次注入、作用域时间窗内、前台应用未变、焦点字段尾部仍含该注入文本且光标仍在末尾（读不到字段/光标时按 `verify_mode` 决定拒绝或 8s 短窗盲删）；选区非空、密码框、提权窗口、已发送/光标移开的文本一律拒绝并提示。字幕模式与微信输入法模式不拦截；命令轮不写会话历史、不参与纠错对，执行前结束上一轮编辑追踪。设计见 `Doc/Plan/voice-edit-commands.md`。
  - **targeted 词/短语删除与替换**（vNext，同 `[voice_edit].enabled` 开关）：ASR final 整句命中「删除刚才的北京」/「删掉刚才的北京」/「把刚才的北京删掉（去掉/删去）」/「把刚才（第一个/最后一个）北京改成（改为/换成/替换为/替换成）上海」时，编辑**最近一次注入文本中**的目标词而非尾部：目标词按连续文本片段精确匹配（≤32 graphemes，替换 ≤64，双端硬上限），无位置限定时仅 1 个精确匹配才执行、多处匹配安全拒绝（提示说明第一个/最后一个），支持「第一个/最后一个」消歧；词可在注入文本的开头/中间/末尾。执行用平台精确选区（macOS AX `kAXSelectedTextRange` / Windows UIA TextRange `Select()`），读回实际选中文本逐字确认 == 目标词后一次 Backspace（删除）或 `paste(pressEnter=false)`（替换），随后光标恢复到字段末尾（不是被改词之后，best-effort）并终验——**终验成功判据是字段文本**（2026-10-31 修订：光标位置/既有选区不拦截，光标未恢复只记日志不判失败），终验通过才更新 `remainingText` 并允许连续编辑。**targeted 动作任何 `verify_mode`（strict/auto/off）下都必须 verified**：读不到字段/光标一律拒绝，不存在 8s unverified 盲改；L1 要求完整剩余注入文本仍是字段后缀（允许末尾一个已记录 `auto_enter` 换行，不用旧「最长前缀」容错——用户手工改动会使目标偏移不可靠）。选区读回不符 → 零删除/零粘贴、恢复末尾光标、记录保留；修改后终验不符 → 不自动重试/不宣称成功，注入记录失效防陈旧偏移，提示用户检查；异步回调带 generation，新注入不被旧回调覆盖。命令轮不粘贴命令文本、不进精修/翻译/纠错对/会话历史；旧字/句/整段指令行为不变（旧解析器优先，targeted 其次）；不带「刚才的」的「把A改成B/删除A」作为自然简写：仅最近一次注入中确实存在 A 才接管执行，无匹配时按普通文本上屏；显式作用域的空目标/空替换/多替换分隔符/否定（不要/别）等异常语法只提示不修改，疑问（吗/呢）与自然简写结构异常回退普通文本。已知限制：语气尾剥离使「改成好吧」类替换得到「好」；targeted 恒 verified 意味着 UIA/AX 不可读的应用一律拒绝（提示不可校验）；UIA 尾部窗口 512 UTF-16 内放不下剩余注入时安全拒绝。
