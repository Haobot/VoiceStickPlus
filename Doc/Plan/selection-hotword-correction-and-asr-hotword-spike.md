# 划词纠错入口 + ASR 热词模型 Spike 设计

> 状态：设计已确认（2026-09-10），待实施。
> 背景：跨轮纠错 M0~M4 已交付（[local-asr-accuracy-and-cross-turn-refinement.md](local-asr-accuracy-and-cross-turn-refinement.md)），
> 真机复测暴露守卫锚点设计边界——目标词从未被正确识别过时（ASR 连续把
> "语气词"识别成"逾期次/鱼妻子/语棋子"），上文锚点建立不起来，正确指令也被拒。
> 用户需求：选中错词→看到修正候选→选择/输入→正确词入表→后续自动纠正。
> 明确否决：逐变体建"错词→正确词"映射表（错法变体多，枚举负担用户不可接受）。

## 方案总览（两条腿，独立推进）

| 腿 | 内容 | 性质 | 量级 |
|---|---|---|---|
| 轻量方案 | 划词纠错入口 + 热词表并入跨轮守卫锚点域 | 产品功能（TDD） | 1~2 天 |
| 模型 spike | transducer + 热词 biasing 评测 | go/no-go 调研 | ~1 天，不动产品 |

## 一、轻量方案

### 1.1 交互流

在现有划词热词入口（`SelectionHotwordManager`，选中→弹层→点击即加）上扩展：

1. 选中错词（如"逾期次"）→ 选区旁弹层出现，**两个动作**：
   - **[＋热词]**：原行为不变（点击即加选中文本）。
   - **[✎ 纠错]**：弹出纠错小对话框。
2. 纠错对话框：错词醒目显示 + 候选列表（3~5 个）+ 手输框 + 确认/取消。
3. 用户点选候选或手输正确词（如"语气词"）→ **正确词**加入 `asr_hotwords`，
   toast 反馈。错词本身不记任何映射。

### 1.2 候选生成

- 上下文：错词 + 跨轮历史最近几轮（`RefineHistory`）。
- 引擎：云端 LLM（`llm_*` 配置存在时）优先；未配置则复用本地精修引擎
  （4B 跨轮常驻 / 1.7B 单句档）。异步生成，对话框先开、候选区显示加载态。
- 近音约束：每个候选与错词**逐字近音校验**（复用 `PinyinSameOrNear`），
  不过校验的候选不展示——防无关建议，用户选择是最终裁决（安全不依赖 LLM）。
- 失败兜底：无 LLM/本地引擎/生成失败 → 候选区显示"无候选"，手输框可用。

### 1.3 生效机制（核心，一处改动）

跨轮纠正管线守卫锚点域从「上文出现过」扩展为「上文 ∪ 热词表」：

- `ApplyPinyinCorrections` 的查找域加上 `asr_hotwords` 整词匹配。
  热词是用户显式确认过的词，作锚点与"上文出现过"安全性等价。
- 生效链：4B 跨轮检测出指令（"逾期次→语气词"）→ 拼音守卫逐字近音 ✓ +
  "语气词"在锚点域（热词表）✓ → 替换放行。**用户只确认一次正确词，
  所有近音变体由近音校验自动容忍。**
- 云端会话受益：正确词进 `asr_hotwords` 后走现有 corpus 热词倾向链路（零改动）。
- 现有热词保护（指令误删热词→回退）保持不变。
- 边界：跨轮开关关 / 4B 缺失时跨轮纠正不生效（云端倾向照旧）；无新持久化。

### 1.4 测试

- 锚点域扩展单测：热词作锚点放行近音替换 / 非近音仍拒 / 热词整词匹配边界。
- 纠错对话框逻辑：候选异步加载 / 近音过滤 / 选择与手输回填 / 原加词路径回归。
- 真机验收：划词纠正"逾期次"→"语气词"入表 → 口述变体验证自动纠正。

## 二、模型 Spike（transducer + 热词）

**核心问题**：识别端热词 biasing 能否纠正常用词同音误识别，且精度代价可接受。

- 模型：`sherpa-onnx-streaming-zipformer-zh-en-2023-11-22`（sherpa-onnx 官方
  热词文档主推中文 transducer，流式双语；spike 内整段推理，不动流式接口）。
- 评测集三组（同源 M0 C 组词表纪律）：
  1. 常用词热词组（核心）：同一批音频跑"热词关/热词开（正确词入表）"两态对比。
  2. 专有名词组（对照，热词传统强项，验证环境正确）。
  3. 精度回归组：通用句子 CER vs SenseVoice 基线。
- 音频：优先真机 dump 原始 PCM（asr_bench 工具链），不足部分 TTS 合成补。
- 判定：
  - **GO**：常用词组热词开命中率显著提升（≥50% 场景翻正）且通用 CER
    相对劣化 ≤20% → 立换基座迭代（流式接口/全链回归/模型分发，独立立项）。
  - **NO-GO**：热词对常用词无效（已知风险：biasing 擅长低频专名）→
    不换基座，轻量方案兜底，报告留档 `m0/`（不进仓库）。

## 三、热词少字变体触类旁通（S3 真机反馈增量，2026-09-10）

**用户场景**：热词表有「口水词」，口述时 ASR 输出长度不等的变体（口水/水池），
纠正不生效。根因三层：守卫等长校验（`CodepointCount(src) != CodepointCount(dst)`
直接拒）＋4B 纠错提示词只锚定「上文」（热词表不进模型视野）＋划词候选
FilterCandidates 同等长口径。

三处同口径放宽（V1/V2/V3，全部 TDD 交付）：

- **V1 守卫近音子序列对齐**（`pinyin_guard.cc`）：dst 比 src 恰好多 1 字且
  src 与 dst 删任一字后的连续序列逐字近音 → 放行（「口水」对齐「口水词」
  删「词」、「水池」对齐删「口」，池 chí/词 cí 韵母交集同音）。只放宽
  「错词漏字」方向：dst 更短、长度差 ≥2 一律拒（杜绝指令截短热词攻击面）；
  语义反转指令（不→很好）因无近音对齐路径天然被拒；热词锚点域校验不变。
  新导出 `NearVariantText`（对称版）供候选过滤共用。
- **V2 4B 提示词热词注入**（`local_refinement_client.cc`）：cross 模式
  user 输入行后插「热词：a，b」行（每轮 user 本就重算，无 KV 缓存代价）；
  系统提示词「上文或热词中出现过」＋教学示例（算法流→算法流程，避开
  线上真实案例防教学复读污染）。
- **V3 划词候选链路**：`BuildCorrectionCandidatesPrompt` 加热词参数（云/本
  两路共用，`win32_app` 传 `config_.asr_hotwords`）＋`FilterCandidates` 改
  `NearVariantText`（划「水池」时候选「口水词」可展示）。

验证：core_tests 全绿（放行/反转拒/差 2 拒/反向拒/锚点域保持/候选保留/
prompt 注入/跨轮热词行）；4B 真引擎冒烟（m0/refine/smoke_hotword_variant.py，
不进仓库）三案例 PASS——热词行触发「水池→口水词」、无热词行不触发、干净句
不误纠热词；1.7B 回退层不出有效变体指令但守卫兜底无害（跨轮能力本就 4B
专属，M0 结论不变）。

## 风险与遗留

- 热词 biasing 对常用同音词的效果未知（K1 核心待验证项）——**已验证**：常用词错例翻正率 71% 有效，但换基座通用精度代价超线，NO-GO（m0/hotword/hotword_transducer_report.md）。
- 4B 分发链路遗留（manifest 条目 + COS 上传 + 下载向导第三条目）独立于本方案。
- 候选生成的本地引擎在无任何模型环境退化为纯手输（可接受）。
