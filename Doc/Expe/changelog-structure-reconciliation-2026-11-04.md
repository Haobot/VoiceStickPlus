# CHANGELOG 结构性缺陷三症状与全量对账方法（2026-11-04 定案）

- 日期：2026-11-04
- 相关文件：`CHANGELOG.md`
- 相关 commit：`cacc2cc`（v2.5.0 发布说明沉淀 + v2.4.10 段勘误）、`6f420be`（全量对账：stray 14 条归位 + 补齐 v2.4.0~2.4.6 缺失段 + 段序修正）
- 触发：v2.5.0 发布说明沉淀入 CHANGELOG 时顺带发现

## 症状（三合一，跨多轮发布累积）

1. **两个流浪 `## Unreleased` 段**：顶部一个（语音编辑批次 1/2，已随 v2.5.0 发布却滞留）、中部一个（卡在 v2.3.8 与 v2.3.6 之间，装着网关 P2/HID 特权注入/离线授权等 v2.3.x 时代 Windows 条目）。已发布内容滞留 Unreleased = 读者误判「未发布」。
2. **版本段与实际 tag 内容错位**：`## v2.4.10` 段里放的「语音编辑指令（基础版）」两条，经 `git log v2.4.10..HEAD` 核实提交（a127c5b 等）实际在 v2.4.10 tag **之后**——即随 v2.5.0 发布；而 v2.4.10 真实内容（音质收紧/RNNoise PoC/遥控器直连）反而从未进过 CHANGELOG。
3. **整条版本线缺段 + 伪 tag 段**：v2.4.0~v2.4.6（2026-09-24~09-28 七个真实发布）在 CHANGELOG 里零记录；「## v2.3.8」段**没有对应 tag**（从不存在 v2.3.8 发布），其条目实随 v2.4.0 MSI 分发。段序也乱（v2.3.6 排在 v2.3.7 前）。

## 根因

- 发布动作里没有「Unreleased 毕业」这一步，新条目按**写作时间**落到「当时最新段」或新开 Unreleased，而不是落到「首发 tag 段」——条目位置随写作时点漂移，累积成错位。
- CHANGELOG 段列表从不与 `git tag -l` 对账，缺段/伪段不可见。
- 发布 release body 过薄（如 v2.4.1 只有 compare 链接）时没有回填渠道，版本段干脆不写。

## 对账方法论（判据式，下次直接照做）

1. **条目归段的唯一标准 = `git tag --contains <commit>` 的最早 tag**（= 首发版本）。条目的写作位置/写作时间/所在段一律不可信。
2. **按 message grep 定位提交常命中后续相关提交**（同一关键词后来者居上）。定位功能原始提交用**核心文件首笔历史**：`git log --all --diff-filter=A --format='%H' -- <核心文件路径> | tail -1`，再对结果做 tag containment。
3. **「入库版本」≠「分发版本」**：macOS 构建产物自 v2.4.7 起才发布，v2.4.1 tag 已含的 macOS 条目按**用户首次可获取的发布版本**归段（归 v2.4.7）并注记「代码自 v2.4.1 入库」。Windows/固件条目两者一致，直接按 tag。
4. **段名无对应 tag = 伪段**：`git tag -l | grep vX` 先验段名存在性；伪段内容找真实首发 tag 并入（v2.3.8 → v2.4.0），原段删除。
5. **release body 为空/仅 compare 链接的版本**：从 git 区间重构——`git log vA..vB --oneline` 挑用户可见项成段（v2.4.1 即此法）；有 body 的近乎逐条搬入。
6. **完整性机器对账**：`git tag -l 'v*' --sort=-creatordate` 与 `grep '^## v' CHANGELOG.md` 做 diff，缺失段一望便知（本次靠它发现 2.4.0~2.4.6 整线缺段）。
7. Windows 系条目与其 macOS 移植版是**两条独立条目**（首发 tag 不同：如小米 2 Pro Windows=v2.4.0、macOS 移植=v2.4.1 入库/v2.4.7 分发），不要合并归段。

## 修复（机制）

- stray Unreleased 全部消费：Windows 系 8 条 → v2.4.0 段；macOS 系 5 条 → v2.4.7 段补录块；电源键详细条目 → v2.5.0 段（替换摘要）。
- v2.3.8 伪段解散并入 v2.4.0 段（段首注记「2.3.8 从未打 tag」）。
- 新建 v2.4.1~v2.4.6 六段（v2.4.2~2.4.6 自各版 GitHub Release body 搬入；v2.4.1 自 git 区间重构）。
- v2.4.10 段重写为真实内容（错位条目移入 v2.5.0 段）；v2.3.7/v2.3.6 段序换正。
- 验证：26 个版本段按新→旧全排列；关键条目全文唯一（`grep -c` 均为 1，仅 v2.4.4「包含 v2.4.3 特性」延续句重复属 Release 原文有意为之）。

## 长期纪律（防复发）

- **发布时 Unreleased 随手毕业**进新版本段（本次 v2.5.0 沉淀即照此执行，顶部 Unreleased 已清）；新版本段紧贴现有段序插入（新→旧）。
- 每次发布收尾跑一遍完整性对账：tag 列表 vs 段列表 diff。
- 改 CHANGELOG 条目前先用 tag containment 验证归属，勿按段落位置推断。

## 遗留 / 观察项

- 无挂起项。v2.3.6 及更早的 v2.3.x/v1.x 段内容未逐条重审（tag 均存在、段序已正；条目级对账收益低，如有新证据再查）。
