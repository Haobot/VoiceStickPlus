# AGC 耳语电平修复：门限语义纠正 + 用真机录音做离线测试向量

日期：2026-10-15
方案：`Doc/Plan/whisper-level-agc-v2.md`（同轮落地）
相关文件：`firmware/components/audio_pipeline/audio_pipeline.c`、`desktop/macos/Sources/VoiceStickCore/PcmPostprocessor.swift`、
`desktop/windows/src/pcm_postprocessor.{h,cc}`、`scripts/e2e_test/atvv_capture.py`、`desktop/macos/Tests/VoiceStickTests/PcmPostprocessorTests.swift`、
`desktop/windows/tests/core_tests_codec_serial.cc`

## 背景与成果

用户反馈「调试会话里的录音都特别轻，轻声说话识别率低」，而「嘴贴麦克风的耳语」是本项目主打场景。
用本机 `~/Library/Application Support/VoiceStick/DebugAudio` 的 29 段真机录音离线分析后定位到 AGC 两处设计缺陷：

1. 旧 `gated = env < -45dBFS ⇒ desired = 1.0` 把耳语（前级包络 -42~-52 dBFS）整段挡在门外 ⇒ **0 dB 增益**；
2. 门限之上被 `MAX_GAIN=+12dB` 截断在 -33 dBFS。

修法：把 -45 dBFS 从「门限」改为「噪声预算」，`MAX_GAIN` +12→+36 dB，本底用 120 ms 冷启动窗估计、
门限 = 本底 +12 dB、大误差 100 ms 快攻。四端同步 + golden fixture 再生。

验证：Python self-test 17/17；macOS `VoiceStickTests` 928/928；C++↔Python 全链 4 组向量**逐样本 bit 级一致**
（输出哈希相同）；固件 `idf.py build` 通过。真机 A/B 待用户配合。

## 经验一：先「反推生效增益」，再谈改参数

耳语段录音是**后级输出**，看不到 AGC 实际给了多少增益，很容易误判成「增益不够大，把上限调高就行」。
本次用一条**可复核的界**把状态钉死：若 AGC 真的给了 +12 dB，输出包络必然 ≥ 4×184/32768 = **-33.0 dBFS**；
而 22:22 session-1/-2 实测包络 p50 为 -52.4/-49.7 dBFS，低于该下界 16~19 dB ⇒ 实际增益只能 ≈0 dB。
离线再把旧算法原样跑一遍这两段录音，输出与输入逐帧一致 —— 两条证据互证「门限封死」而非「上限不够」。

**教训：DSP 链路只看输出无法判断内部状态时，先用「若假设成立则输出必然满足某不等式」构造判据，
再去调参；否则会把「上限调高」（本次实测对门限封死的两段完全无效，输出一字未变）。**

## 经验二：真机录音可以当真值向量 —— 但必须先确认「它没被处理过」

耳语段生效增益 ≈0 dB，意味着这些 `.ogg` **本身就是前级信号**，可直接当 AGC 输入做离线 A/B
（比合成正弦真实得多）。判据就是经验一的不等式。反之，10-13 的近场大声录音是后级输出，只能当
「大声输入」用，不能反推前级。

## 经验三：AGC 的「噪声门」三种语义必须分清

- 「门内不给增益」（旧实现，`desired=1.0`）→ 安静场景直接废掉 AGC，且句间停顿后起音塌陷；
- 「门内冻结/缓回」（本次第一版草案）→ 高增益下间隙底噪被整体抬高；
- 「门内**给噪声预算上限**」（最终实现，`desired = min(TARGET/env, -45dBFS/env)`）→ 既有硬上限又保留
  增益连续性，实测嘈杂合成场景（耳语+噪声 -40~-50 dBFS）输出全部未被放大。

另一个必须算清的量：**固定门限与真实噪声/轻声的区间重叠**（`software-agc.md` 附录已记录 -44 与 -40 dBFS
仅差 4 dB）⇒ 纯电平方案不可能区分「轻声语音」与「同等响度的噪声」，只能把判别交给频域（桌面端 RNNoise）。
本次的决策是：**安静房间尽量拉起，嘈杂房间自动退回不放大**（安全失败方向）。

## 经验四：注释里的时间常数必须回算

`AGC_GAIN_GATE = 0.9999961` 注释写「缓回 ~1s」、`AGC_GAIN_DOWN = 0.73162` 写「2ms」，按
`exp(-1/(fs·τ))` 回算实际是 **τ≈16 s** 与 **τ≈0.2 ms**（差 16 倍 / 10 倍）。改这类常量前先回算，
否则会把「门内行为」判错方向（本次首版草案就据此写成「把 τ=1s 改成 3s 冻结」，方向正好相反）。
判据：`τ = -1/(fs·ln(c))`。

## 经验五：离线合成要复现「AGC 真正看到的输入」

回放录音做合成时注意：设备侧 `click guard`（前 120 ms 静音 + 淡入）作用在 **AGC 之后**，所以录音头部的
静音在真机 AGC 输入里并不存在。若直接拿录音+噪声做合成，冷启动窗会读到「数字静音」→ 本底被低估 →
噪声被误放大，得出错误结论。正确做法：合成时把前 200 ms 用纯噪声铺满（模拟真机 AGC 见到的环境声）。

## 经验六：本底估计器要比「最小值」更稳

冷启动窗取包络**最小值**时，首样本包络从 0 爬升、单次极低样本都会把本底钉在近 0 ⇒ 门限塌到绝对下限、
噪声被放大。三处修正缺一不可：①首样本直接取 |x|（跳过包络爬升）；②跳过前 5 ms；③本底低于
`-90dBFS` 视为不可信 → 取绝对下限；④本底估计上限钳到 -45 dBFS（防冷启动窗整段是语音时把门限抬到
语音之上、反把语音压死）。

## 经验七（v2.1 追加，最重要）：测试向量的「形状」必须与真机一致 —— click guard 顺序坑

v2 上线后用户复测仍「太轻」。真机根因：**AGC 在 click guard 之前**，按键咔哒进入 AGC 的 300ms 慢释包络，
把冷启动窗量到的「本底」顶成咔哒尾部 → 本底被钳到 -45dBFS → 门限 -33dBFS → 耳语（-46dBFS 包络）永远低于门限
→ 整场增益被压在 ≈1.1 倍（即用户听到的原始拾音电平）。

**为什么离线测试全绿却漏掉**：离线向量是 `.ogg`（recording），而 recording 是 **click guard 之后**的信号——
头部 120ms 已被静音/淡入，本底估计自然干净；真机 AGC 看到的却是 guard 之前的信号。同一段音频，
「AGC 的输入」和「落盘的输出」形状不同。

三条可复用的判据/做法：

1. **凡是用真机录音当离线输入，先问一句「它经过谁的后处理」**——本次录音过了 click guard，而 AGC 在其之前；
2. 涉及「会话起始 x 毫秒」的算法（AGC 本底、VAD、静音检测），离线合成时要**显式复现真机的起始形状**
   （本次应把录好的咔哒/静音区补回 AGC 输入端再测）；
3. 新固件上线后第一次真机复测**必须看新录音的电平**（不是看代码/看编译通过）——本次正是靠 19:24~20:01 的
   15 段新录音（峰值 -10~-40dBFS，与「AGC 生效」应有的 -12dBFS 包络不符）才发现没生效。

附带结论：**固件的 click guard 必须放在 AGC 之前**（否则它只保护了输出，保护不了 AGC 的内部状态）；
本底估计只统计「有效信号」（跳过前置无效区 + 数字静音），比按固定窗口取最小值稳。

  与 Python 的对拍已 bit 级一致，不能替代 MSVC 全量。
- 真机 A/B：`debug_audio_cache = true`，同文本耳语 + 近场大声各若干段，判据见方案 §6。

  偏吵，先降预算；若耳语仍偏轻，再抬上限（两者互相制衡）。
