# macOS 本地模型：设置 UI + 应用内模型下载 + 内嵌 llama.cpp 精修/对齐

## 先回答你的问题：现在模型都是通过 Ollama 调用的吗？

**不是，目前是三种运行时并存：**

| 功能 | macOS 现状 | Windows 现状 |
|---|---|---|
| 本地 ASR（SenseVoice） | 内嵌 sherpa-onnx dylib（dlopen），**不走 Ollama** | 内嵌 sherpa-onnx DLL |
| 本地文本精修 | **未实现**（只有云端 OpenAI 兼容精修） | 内嵌 llama.cpp（静态链入）+ GGUF |
| targeted 目标词对齐 | **唯一走 Ollama 的**（`/api/chat`，回环强制） | 未接（M3） |

本方案后 macOS 将变成：ASR 内嵌 sherpa-onnx + 精修/对齐内嵌 llama.cpp，**不再依赖 Ollama**，与 Windows 运行时统一，模型全部走 COS 清单分发。

## 已确认的决策

1. 仅 macOS（Windows 已有同款设置+下载向导，不动）。
2. LLM 走**内嵌 llama.cpp**（非 Ollama），GGUF 模型走 COS 清单下载，用户零外部依赖。
3. 连带实现 macOS 本地精修（editform 形态，评测最优 Qwen2.5-3B/1.5B）。

新分支 `feat/macos-local-model-settings`，基于 `feat/local-model-fullstack`。

## Phase A：设置 UI + ASR 模型下载（先见效，~2 天）

**A1. Provider 下拉本地虚项**（`SettingsWindowController.swift`，完全镜像 Windows 已实施的 D1/D2 契约）：
- 「语音识别 → 服务提供方」下拉末位加「本地语音识别（离线，无需云端密钥）」；不新增 `ASRProvider` 枚举值——选中 = `local_asr.enabled=true`，`asr_provider` 保留云端值（切回无缝）。
- 本地选中时才显示（复用现有 `updateVisibility()` + `resizeWindowToFit()` 模式，`SettingsWindowController.swift:454-499`）：模型目录行（编辑框+浏览…，空=默认目录）、状态行（✓ 模型就绪 / ✗ 未找到 + **下载模型…按钮**）；同时隐藏 API Key/资源 ID 行。
- 索引映射抽成纯函数（对齐 Windows `provider_combo.h` 的 D4 做法）便于单测。

**A2. 模型下载器**（新 `VoiceStickCore/ModelManifest.swift` + `ModelDownloader.swift`）：
- 清单为**编译期内置常量**（对齐 Windows `model_manifest.cc` 的「不做远端清单」决策），条目：SenseVoice `model.int8.onnx`(239MB)+`tokens.txt`、**sherpa-onnx v1.13.7 osx-arm64 dylib 包**（约 25MB，新增——否则下完模型依然跑不起来；现状脚本只从 GitHub 下 dylib，国内必挂）、后续 Phase B 再加两个 Qwen2.5 GGUF。
- 每条目 4 源回退：`dl.davenger.cloud` → COS 新桶直连（**注意 Windows manifest 里还留着旧桶 fallback，Swift 版只用新桶**）→ ModelScope → GitHub。流式下载 + 全量 SHA-256（复用 `FirmwareManifest.swift:191-197` 的 CryptoKit 校验形状）+ `.part` 断点续传（Range，对齐 Windows `model_downloader.cc` 语义）+ 原子改名。macOS 目前没有任何带进度的下载 helper（全是一次性 dataTask），需要新写 delegate-based helper。
- 安装布局与现状一致：模型 → `~/Library/Application Support/VoiceStick/models/sense-voice-int8-2024-07-17/`，dylib → `models/sherpa-onnx/lib/`。装完即被 `resolvedModelsDir()`/`librarySearchPaths()` 现有逻辑消费，`setup-mac-local-asr.sh` 保留为无 GUI 兜底。

**A3. 下载窗口**（新 `ModelDownloadWindowController`）：仿 `FirmwareUpdateWindowController` 的进度条+速度+ETA+取消 UI（`update(progress:)`/`finish(result:)` 模式），条目勾选（ASR 必选锁死，LLM 可选）。下载成功回填模型目录并刷新状态（用户仍需点保存，与 Windows 一致）。

热更链路已存在不用动：保存 → `onConfigChanged` → `coordinator.updateConfig` → `ASRClientFactory` 热切换 `LocalAsrClient`。

## Phase B：内嵌 llama.cpp 引擎（~2.5 天）

**B1. 源码获取**：新 `scripts/fetch-llama-cpp.sh` 拉取 **pin b10868**（与 Windows `CMakeLists.txt:269` 完全同版本）tarball，SHA-256 校验后解出最小推理集（ggml CPU + llama core，Build 共享库关闭）到 `desktop/macos/Vendor/llama-cpp/`（gitignored）。`Package.swift` 用 FileManager 探测目录存在才声明 `CLlamaCpp` C++ target（未拉取时包照常构建——与 CSherpaOnnx「header-only 无 dylib 也能构建」同思路）；`build-macos.sh` 首步自动跑该脚本。选 fetch 而非提交源码：对齐 Windows FetchContent 语义（Windows 也不提交 llama.cpp 源码），repo 不增 10MB+。
- **Metal 后端本次不做**（Windows 也是 CPU-only，先对齐；M 系 CPU 跑 1.5B/3B Q4 够用，后续再优化）。

**B2. 引擎封装**（新 `VoiceStickCore/LlamaCppEngine.swift`，移植 Windows `llama_cpp_engine.cc` 语义）：ctx 2048、贪心采样、**few-shot system prompt 的 KV 前缀复用**（评测 70ms 延迟的前提，必须移植）、多轮续跑。ChatML 手工模板（Qwen2.5 原生 ChatML）。

**B3. 模型清单 v2**：新增 `Qwen2.5-1.5B-Instruct-Q4_K_M`（~1GB，对齐档）与 `Qwen2.5-3B-Instruct-Q4_K_M`（~2GB，精修档）GGUF，SHA-256 锁定，进下载向导可选项。默认档位：对齐→1.5B、精修→3B（各自按评测最优）；config 可用路径覆盖。两引擎懒加载（对齐引擎首次 targeted 未命中才加载），同时常驻约 3.2GB 内存——设置里如实显示。

**B4. 对齐迁移**：`LocalAlignClient`（Ollama HTTP）退役删除；`VoiceTargetedAlign.swift` 的 few-shot 消息与枚举约束输出解析保留复用，推理调用改走内嵌引擎。配置：`local_align_url` 废弃（保留解析兼容不写入）、`local_align_model` 语义变为 GGUF 路径覆盖（空=默认 1.5B 档）、`local_align_enabled`/`local_align_timeout_ms` 不变（超时 3000ms 兜底 CPU 预填）。

## Phase C：本地精修 editform（~1.5 天）

**C1. 精修管线**（新 `VoiceStickCore/LocalEditformRefiner.swift`，镜像 Windows 三层）：L1 规则（det v5，从评测 harness `deterministic_clean()` 移植进生产）→ L2 editform（LLM 只输出「错词→热词原形/删除：片段」指令，提示词从 harness `EDITFORM_PROMPT` 原样移植）→ L3 守卫（`apply_edit_instructions()` 移植：替换目标必须在热词、错词必须字面存在）。「模型出指令、守卫代码执行」是既有房规，damage=0 由守卫保证。
- 路由：顶层 `refine_enabled=true` 且本地 ASR 会话 → 内嵌 editform；引擎缺失/失败**逐层回退最差不劣于 L1 规则**（镜像 Windows 降级语义，设置里 △ 明示）；云端会话照旧走云端 LLM。
- `[local_asr]` 新增 `refine_num_threads`（默认 4）与 `refine_model`（GGUF 路径覆盖，空=默认 3B 档）；不做 cross_turn（Windows 独有特性，不在本里程碑）。

**C2. 设置区块**：本地 provider 选中时显示「本地文本精修」复选框 + 模型状态行（✓ 3B 就绪 / ✗ 缺失将降级规则级 / 下载入口）；「语音编辑」区块内加「目标词本地对齐」行（它服务于云端+本地两种 ASR，不挂在 provider 下，挂在 voiceEdit 开关的条件区）。

## Phase D：评测复测 + 发布配套 + 文档（~1.5 天）

**D1. 评测复测（必做，task-shape 纪律）**：评测是在 Ollama 上跑的，换内嵌 llama.cpp 后同模型同量化理论等价但仍需实证——新 CLI `Tools/LlamaRefineCli`（仿 AsrReplayCli）把评测样本集喂给内嵌引擎，复用 `scripts/local_model_eval/metrics.py` 对拍：精修 damage 必须为 0、CER 不劣于 1.67% 基线；对齐准确率对拍 qwen2.5:1.5b 基线。**同时实测 CPU 延迟：若 3B 精修 p50 超 2s，默认档降 1.5B 并记录**。

**D2. COS 上传（发布侧依赖，Mac 本机无 COS 凭据）**：需上传 sherpa dylib 包 + 两个 Qwen2.5 GGUF 到 `models/`，走 publish-mac CI 轨道或你手动跑 `cos_uploader.py`；`Doc/Ref/cos-distribution.md` 补清单条目。**这是唯一需要你配合/决策的环节**，App 内功能可先开发完等上传。

**D3. 测试**（全走 `swift run VoiceStickTests`）：
- 清单同步对拍：测试解析 `scripts/pack_local_models.py` 常量 == Swift manifest（第 4 处同步点用测试锁死，不再靠人肉）。
- 下载器：URLProtocol mock 多源回退/SHA 失败切下一源/`.part` 续传 Range/原子落盘。
- Provider 映射纯函数、精修守卫用例（从 harness 移植）、对齐引擎路径（fake engine）。
- 引擎真实冒烟：模型/Vendor 未就位时 SKIP（不伪造结果房规）。
- UI 验收按既有 AX 自动化模式（托盘→设置窗→条件行显隐）。

**D4. 文档**：`Doc/Ref/desktop-config.md`（UI 入口、新键、`local_align_url` 废弃）、`cos-distribution.md`、`Doc/Plan/local-first-voice-stack.md` M2 状态更新、AGENTS.md Hub 提示补一行（本地模型设置入口与 Vendor 构建前置）。

## 风险与对策

- **CPU 延迟不确定**（评测是 Metal 口径）：KV 前缀复用是关键，D1 设降级预案（3B→1.5B 默认档）。
- **llama.cpp SwiftPM 集成坑**（C++20、unistd 等）：fetch 脚本 + 条件 target 保证未拉取时不破坏现有构建；`VOICESTICK_ARCHS=arm64` 环境不变。
- **GGUF 体积**（3B ≈ 2GB 下载）：下载器断点续传 + 可选项默认不勾。
- **Windows manifest 旧桶 fallback stale**（`model_manifest.cc:32`）：Swift 版只用新桶；Windows 侧修正留给 M1，本任务不动 Windows。

## 验收标准

1. 设置里选「本地语音识别」→ 出现模型目录/状态/下载按钮；点下载装完 → 状态 ✓ → 保存 → 说话即出字（无需重启）。
2. 本地精修开：说错词被 editform 修正，damage=0（守卫保证+复测实证）。
3. 语音编辑目标词对齐：不装 Ollama 也能命中（内嵌 1.5B）。
4. 全程不依赖 Ollama / 不需要云端密钥；模型缺失时诚实报错/降级并在设置明示。
5. `swift run VoiceStickTests` 全绿（含清单对拍、下载器、守卫）。

预计总量 ~6-8 个工作日；A 完成即可先给你真机体验本地 ASR 的完整开箱流程，B/C/D 随后。
